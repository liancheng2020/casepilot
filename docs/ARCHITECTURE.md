# 架构与边界

## 主线

CasePilot 聚焦通用订单的支付异常调查与处置，不绑定特定公司或商品业务。当前动作仅包括对账补偿与异常工单，不包含完整售后、物流或自动退款。内置测试数据与模拟支付接口；模型和飞书可真实连接，业务数据仍独立于生产系统。

```text
Web / 飞书消息
  -> 身份和商家范围 -> 持久化任务与去重回执
  -> Agent 循环：模型选择工具 -> 校验 -> 只读执行 -> 证据 -> 模型再决策
  -> 信息不足暂停 / 调查完成 / 人工接管 / 待确认提案
  -> 运营确认 -> 重新核验版本与规则
  -> 同一 SQLite 事务：业务写入 + 动作账本 + 任务状态
  -> 回查 / 结果未知时查原账本，不盲目重试
```

模型只决定调查工具、澄清和建议，后端决定是否允许执行。写动作不是模型可用工具；没有退款、Shell、任意 SQL 或直接修改支付状态的工具。

首版使用小型显式循环，不依赖 Hermes、LangGraph 或 MCP。当前工具注册是进程内 Function Calling，**不能宣称已经接入 MCP**。渠道和模型提供者可替换，业务规则与审批执行不随模型更换而变化。

## 谁拥有哪个状态

- 用户提供唯一订单号，或确认候选；模型不得从多个候选猜一个。订单 ID 始终为 19 位字符串，金额使用整数分。
- 查询只在当前商家范围内。订单与支付来自沙盒后台，不把客户“我已经付款”的描述当作支付成功。
- 模型每轮最多 4 个工具；澄清、提案、结束必须独立调用。参数、权限或证据错误作为工具结果反馈；累计 3 个工具错误转人工。
- 单任务请求、工具预算在重启和重新调查后不重置；请求发出前保存预算。终止后迟到的模型响应或异常不覆盖用户取消。
- 提案引用有效证据，包含订单版本、支付版本、规则版本、有效期和后端计算的 SHA-256 内容摘要。摘要不是数字签名，不能抵御有数据库写权限的攻击者。
- 运营确认只能提交当前提案 ID，不能趁确认修改动作参数。执行前重新检查身份、版本、有效期和业务规则。
- 对账条件包括订单待支付、渠道成功、订单和商家一致、金额币种一致、交易号存在；关单、退款或金额冲突不能直接改成已支付。
- 异常工单创建不改变订单；执行时重新查已有工单，复用原记录。唯一提案 ID 和稳定幂等键防止同一动作重复执行。

## 状态与恢复

`queued -> investigating -> needs_input / awaiting_approval / completed / handoff`

用户补充后重新入队；提案可以拒绝。确认后进入 `executing`，事务完成后为 `completed` 或演示 `result_unknown`。旧提案因状态或有效期冲突进入 `conflict`，重新调查生成新 epoch；旧证据仍保留审计，但不参与新提案。

任务、证据和工具消息保存在 SQLite。恢复调查时复用已保存结果，未落盘的只读查询可能再次执行。等待审批的任务不会被重启自动批准。未知结果按原提案查动作账本并核验后台，不重新生成幂等键。

本地沙盒的业务写入、账本、任务状态共享同步事务，写入回查失败会回滚。**这不是远程支付系统的分布式 exactly-once 实现。** 接真实业务接口时需要下游幂等协议、结果查询、事务 outbox 和对账机制。

单数据目录进程锁阻止多个服务同时调度；任务 CAS 防止旧对象覆盖新状态。首版不包含多进程工作队列、按金额计价的费用限额、生产监控或高可用保障。

## 证据化结论

工具原始结果保存为带 ID、时间和调查 epoch 的证据。`finish` 必须提交结构化 `finding`；`propose_action` 的动作类型也接受后端规则检查。展示的事实只能来自模型实际引用的、本轮成功的订单、支付、工单与回调快照，结论类型必须匹配这些记录。

不是“引用 ID 存在就通过”：结束调查和生成提案还检查**所引用订单与支付的版本**是否仍等于后台版本。重新读取新证据并不会使未更新的旧引用重新有效。异常工单不能凭空提出，待补偿或证据不足不能仅用 `resolved` 结束。

UI 将调查时事实、证据支持的判断、尚未确定、模型原始解释、实际执行结果分开。来源图标跳转到对应工具记录。`modelAnalysis` 保留模型原文供审核，但不作为权威总结、提案理由或执行结果；`assessment` 来自领域规则，不是一个额外的 LLM 裁判。

这能约束状态与金额相关主张，不能自动判断所有自然语言解释的真实性；后续仍需独立语义评测和真实使用者审核。

## 隔离演示与评测预算

`npm run demo` 新建 `data/demos/session-*`，不删除已有数据库，不复用被演示动作改变的订单。默认显式关闭模型与飞书，即使 `.env` 已开启；`--model` / `--feishu` 必须显式选择。飞书联调前先停止使用同一应用的其他进程，避免多个连接争用消息。

`MODEL_BUDGET_FILE` 非空时，外部请求前在独立 SQLite 文件中原子递增用量；同一文件可由评测与服务共享，失败、超时及进程中断已预留的请求也占额度，SDK 无隐藏重试。文件上限不符时拒绝启动，不能通过重启隐式提高预算。`MAX_TOTAL_MODEL_REQUESTS` 默认 60；不配置预算文件时仍受单任务限制，但没有这项跨进程总上限。

这是请求数上限，不是精确金额预算。每个付费评测批次应使用明确上限与独立预算文件，不能删除文件来伪装未用过额度。

## 飞书入口

1. 在自己的飞书个人版或获得授权的测试组织创建自建应用，添加机器人能力。
2. 仅开通 `im:message.p2p_msg:readonly`（读取发给机器人的私聊）与 `im:message:send_as_bot`（以机器人身份回复）；无需通讯录和群聊历史权限。
3. 在本机 `.env` 填写 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，设 `FEISHU_ENABLED=true`，启动常驻服务。密钥不写前端、不提交 Git。
4. 在“事件与回调”选择 SDK 长连接接收，订阅 `im.message.receive_v1`，发布到指定测试人员。长连接须先建立，平台才能保存该接收方式。
5. 私聊机器人发送“身份”，获取自己的 `tenant_key` 和 `open_id`；填写 `FEISHU_TENANT_KEY`、`FEISHU_ACTOR_MAP` 后重启，例如 `{"ou_test_cs":"service","ou_test_ops":"operations"}`。示例 ID 不能照抄。空名单仅允许身份发现，绝不自动赋予业务权限。
6. 配置测试人员可访问的 `PUBLIC_BASE_URL`；本机链接只能在运行服务的电脑访问。先用规则模式和合成订单核对收发、补充、审批及后台结果，再接真实模型。

机器人文字命令：

```text
订单 9223372036854775801，客户说已支付，请查清楚。
补充 <任务UUID> <订单号或说明>
确认 <任务UUID> <提案UUID>
拒绝 <任务UUID> <提案UUID>
核对 <任务UUID>
查询 <任务UUID>
身份
```

也支持依次对应上述动作的 `reply / approve / reject / verify / query` 命令，英文不区分大小写。两种入口使用同一权限与幂等服务；缺少动作前缀、仅以任务 UUID 开头的消息拒绝处理，不猜测用户想补充还是批准，也不创建新任务。

仅接收真实用户发送的私聊文本，拒绝群聊、机器人消息和非文本附件。业务只接受配置组织与 `open_id`，消息里的“管理员”声明不授予权限。入库后立即返回事件处理器，模型与回复不阻塞平台 ACK。消息 ID 去重持久化，通知用稳定 UUID；发送目标来自已验证的私聊事件，不接受用户提供的任意回复 URL。身份发现只把当前发送人的自身标识回复给本人，不查通讯录。

长连接握手成功不等于消息订阅、可用范围和发送权限都正确，必须实际私聊验证。工作台区分配置启用和 SDK 实际连接状态。通知暂未实现可靠 outbox；发送失败或 ACK 后重启可能丢通知，可用“查询”命令恢复查看。重启不会自动批准提案。首版使用文字命令，不包含交互卡片和生产 SSO。

## 部署

使用常驻 Node.js 服务并挂载持久数据目录：`npm ci && npm run build && npm start`。非本机监听必须设置至少 24 位 `WEB_ACCESS_TOKEN`，并使用 HTTPS 反向代理。SQLite、进程锁与飞书长连接不适合直接当作 Vercel Serverless 部署。

升级界面或示例商品不会迁移历史任务、证据或订单。内部测试租户标识保留兼容，不代表公司业务接入；需要全新示例时使用 `npm run demo`，不要清空已有验证数据库。

## 安全与可信边界

Web 的共享令牌和可切换演示身份只用于合成资料展示，**不是生产认证与角色管理**。远程部署需要 HTTPS 和访问控制；禁止接入真实订单、客户个人信息或生产支付凭证。

Zod 校验字段结构，证据引用与领域判断保护结构化结论，版本和业务规则保护写入；这些不能保证模型原文的每一句解释被证据支持，也不承诺完整抵御提示注入或任意语义误判。

请求次数在发出前记账，token 是服务返回 usage 的累计值；超时无法得到的用量未补计。没有把 token 估算成费用，避免对缓存与价格做无依据推断。
