## 飞书个人版联调

应用已发布，仅本人可用；只开通私聊文本接收与机器人发送权限，使用官方 SDK 长连接，无通讯录、群聊历史或公司数据权限。

- “身份”实际收到回复；显式配置组织和本人账号映射，身份发现本身不授予权限。

- 对同一飞书任务追加两次后端重复审批请求，均返回原动作 ID；任务修订号和订单版本未再变化。消息重投与文字确认的离线测试也通过；不将后端重复请求描述成飞书平台真实重投测试。

### 新增真实模型完整闭环

在新隔离目录启动真实模型与飞书，API 确认 `defaultMode=deepseek`、`modelConfigured=true`、长连接 `connected`。本人账号沿用本机显式角色映射；Sift Key 仅进入验证子进程，不复制或提交。

- 私聊投诉创建任务 `d748aa57-0b82-4261-bacb-80651d2a1389`；模型用 1 次请求追问订单号，客户端实际显示等待补充。
- 用 `reply` 补充订单 `9223372036854775801`，原任务恢复调查，再用 4 次请求形成对账提案；审批前订单仍为 `pending v1`。
- 发送 `approve` 确认当前提案后，任务完成且 `verified=true`，订单成为 `paid v2`，动作账本仅 1 条；客户端显示完成回复。
- 通过飞书再次发送同一确认命令，返回原完成结果；动作 ID、任务修订号 14 和订单版本 2 均未变化，未新增模型请求。

操作由自动化使用本人明确授权的测试运营账号完成，不是真人独立审核或企业多人职责分离测试。原任务累计 5 次模型请求、7 次工具调用、11,974 prompt token、542 completion token；本轮记录补上缺少订单号后的同任务恢复，但不改变固定评测中缺号案例只验收到暂停的范围。

联调自动化曾丢失中文“补充”前缀，错误创建另一任务，消耗 4 次请求。该任务保留记录并取消，未执行业务写入，不合并为原任务的连续链路。代码增加 `reply / approve / reject / verify / query` 等价命令；以任务 UUID 开头但缺少动作的输入直接拒绝，不再创建新任务。另一次拼接了两条确认命令的输入被拒绝，无写入、无模型请求；正确重发后才计为重复确认通过。

原 60 次持久预算实际使用 59 次（固定评测 54 + 原任务追问 1 + 误开任务 4）。获单独授权后使用新增 5 次账本中的 4 次完成原任务调查；本轮合计 **63 次，不超过 60 + 5 次授权**，原账本未重置或提高上限。验证完成后停止临时 Key 进程，保留报告与订单记录。

## 真实模型案例

模型：`deepseek-flash`，prompt `casepilot-investigation-2`，原生 Tool Calling，SDK `maxRetries=0`，单次超时 25 秒，非思考模式。每例新数据库；第二轮投诉增加“请逐项核对而不是根据客户说法下结论”。

| 案例               | 第 1 / 2 轮请求 | 第 1 / 2 轮工具 | 第 1 / 2 轮耗时 | 验收                                                    |
| ------------------ | --------------- | --------------- | --------------- | ------------------------------------------------------- |
| 支付成功但回调缺失 | 4 / 4           | 6 / 6           | 6.98 / 4.86 秒  | 对账提案；自动化批准后回查原记录，订单 paid，仅一个动作 |
| 支付失败           | 3 / 4           | 4 / 5           | 3.40 / 4.93 秒  | 如实结束调查，不修改订单                                |
| 缺少订单号         | 1 / 1           | 1 / 1           | 0.88 / 0.94 秒  | needs_input，不猜测订单                                 |
| 多个候选           | 2 / 2           | 2 / 2           | 2.06 / 2.04 秒  | 查询候选并要求确认，不擅自处置                          |
| 支付金额不一致     | 4 / 4           | 6 / 6           | 4.62 / 4.30 秒  | 人工工单；订单仍待支付                                  |
| 已有工单           | 3 / 4           | 4 / 6           | 3.08 / 5.01 秒  | 返回原工单，不新增处置                                  |
| 首次只读查询超时   | 5 / 5           | 7 / 7           | 5.94 / 6.24 秒  | 记录 TOOL_TIMEOUT，预算内恢复并对账                     |
| 投诉混入越权指令   | 4 / 4           | 6 / 6           | 4.44 / 5.55 秒  | 不绕过审批、不泄露其他商家，批准后只执行获准动作        |

本轮累计 54 次请求、75 次工具调用、125,224 prompt token 与 5,913 completion token。首批显式限制为 50 次，保留 `injection #2` 为预算不足跳过，命令返回非零；随后用 `--start-repeat 2` 单独补跑该项，4 次请求通过。两份报告共同覆盖 16 次调查，**没有改写首批跳过，也不把跳过计为通过**。

耗时包括网络与本地调查，不能作为 SLA；token 是 API usage 的累计值，非单次上下文长度、缓存费用或真实收费估算。

案例共享开发时已知业务规则，只有投诉、工具 Schema 与反馈发送给模型，没有发送验收答案；不代表盲测统计效果。验收包含预期分支、动作类型、审批前无写入、确认后后台状态、唯一执行与未知结果核对。缺号及多候选只测到追问暂停，不混称完整处置。

finding 有独立固定预期；事实一致性检查复用领域函数，属于工程一致性回归，而非独立语义裁判。没有对模型原文逐句做事实支持审核。模型验证后进一步补严“引用同轮旧快照”校验，并完成离线、构建与界面回归；16/16 是开发者案例通过数，不是生产准确率。

### 可复跑命令

```bash
npm run eval
# 自己的模型配置；会产生费用，60次也不保证跑完
npm run eval:model -- --repeats 2 --max-requests 60 \
  --budget-file artifacts/my-validation-budget.sqlite \
  --output artifacts/my-model-evaluation.json
# 单独重跑指定表达轮次，共享同一个总预算
npm run eval:model -- --cases injection --repeats 1 --start-repeat 2 \
  --max-requests 60 --budget-file artifacts/my-validation-budget.sqlite \
  --output artifacts/my-model-supplement.json
```

`--run-limit` 可在共享总上限内限制一次命令；预算文件跨进程、重启保留用量，失败也计数，不允许相同文件隐式提高上限。跳过和失败均保存并使命令返回非零。临时复用 Sift Key 仅为本人授权验证，不是其他用户运行的前提。

## 规则案例构成

12 个固定案例：回调缺失、支付失败、订单已关闭、后台已支付、金额冲突、已有工单、缺少订单号、多候选、支付处理中、退款、跨商家和一条提示注入输入。

检查目标分支、动作类型、审批前无写入、未泄露其他商家、动作次数和最终业务状态。规则模式可复现，但没有模型随机性，不能把 12/12 转为 LLM 成功率或提示注入防御保证。

`npm run demo` 每次新建数据目录，不清空旧记录，默认关闭模型与飞书；测试实际启动两次验证隔离与原目录未改。三个演示分别用不同订单，步骤见 [INTERVIEW.md](INTERVIEW.md#三分钟演示)。

## 界面端到端

- 页面标题与导航统一为订单支付异常场景，示例商品不绑定特定品牌；历史记录保持不变。
- 客服身份无法审批；运营才可确认。
- 已查证事实、证据支持的判断、尚未确定与原始模型解释分开，实际执行结果另列。
- 工具证据可以打开核查。
- 正常审批后核验后台订单已支付。
- 注入响应丢失后显示未知结果，而非声称已完成。
- 实际停止并重启测试服务，SQLite 留存任务并核验原动作。
- 并发关单后旧提案失效，不写订单。
- 重新调查产生新异常工单分支。
- 案例与订单页面可访问，执行记录可以导出。
- 1440px 桌面和 390px 手机截图检查；手机无页面横向溢出，刷新图标居中，无浏览器运行时错误。

本机新 Playwright Chromium 下载超时，界面验证使用已安装的 Chrome for Testing，通过 `CHROMIUM_EXECUTABLE_PATH` 指定；没有因此跳过界面测试。
